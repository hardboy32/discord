Privacy Policy

Effective date: November 18, 2026 · Last updated: November 18, 2026

This Privacy Policy describes how the HARD BOY Discord Bot and its optional web dashboard (together, the “Service”) process information when people use the bot in Discord or sign in to the dashboard.

Application: HARD BOY Discord Bot · Discord Application ID: 812717050753450004 · Dashboard: https://discordbot.up.railway.app

1. Information the Service processes

  • Discord account and server information: Discord user IDs, usernames or display names, server IDs and names, channel and role IDs and names, and permission information needed to provide bot features and authorize dashboard access.
  • Dashboard sign-in: the dashboard uses Discord OAuth2 with the identify and guilds scopes. It stores the minimum session information (user ID, display name, server ID and expiry) for up to 30 days. The Discord OAuth access token is used for sign-in and is not saved to disk. A signed, HttpOnly, Secure session cookie is stored in your browser.
  • Commands and feature records: depending on enabled features, this can include warning reasons and moderator names; XP and level totals; virtual currency balances; poll votes; giveaway entries and winners; invite attribution; suggestions and custom responses; stream-alert creator names; and feature configuration. Records may contain Discord user, server, channel, message or role IDs.
  • Messages and moderation: when AutoMod is enabled, the bot reads message text to check the configured invite-link, blocked-word, spam and mass-mention rules. A matching message may be deleted; the moderation log records the author and reason, not the deleted text. Message edit/delete event logs record the author and channel and do not record message content.
  • Music requests and media: the bot processes song titles or links submitted to the configured music-request channel and track metadata needed for playback. Messages written by members in that selected request channel are automatically deleted during a daily cleanup cycle; bot-generated messages and the music player panel are retained. Music searches and links may be sent to the relevant music source or media extraction provider to resolve playback. Uploaded audio files and music artwork may be stored on the operator's Railway storage volume.
  • AI messages (only when AI is enabled and invoked): the prompt directed to the bot and a limited amount of recent conversation context are sent to Groq to generate a reply. The bot keeps a short conversation history temporarily in process memory; it is not written to persistent bot data files and is cleared when the bot process restarts.
  • Support tickets: if ticket features are enabled, the bot creates private ticket channels. When a ticket is closed, it can export up to the latest 1,000 messages to a transcript in the channel selected by the server administrator. A transcript may contain message text, author names and attachment URLs.
  • Browser data: the dashboard uses a session cookie for authentication. It may store up to 20 recently played track titles and URLs in the user's own browser local storage.

2. How information is used

Information is used as needed to authenticate server administrators; check permissions; process commands and interactions; provide music, moderation, welcome, ticket, community, XP, economy and notification features; maintain configuration and feature state; protect the Service from abuse; and troubleshoot failures.

3. Storage and retention

  • Persistent bot settings, warnings, community feature data, music-panel references, uploaded welcome artwork, fallback music artwork and saved audio files are stored in the Railway volume configured by the operator (normally /app/data).
  • Persistent feature records are generally kept until a server administrator or operator deletes them, clears the relevant feature data, or removes the stored bot data. Disabling a feature does not necessarily delete records already created by it.
  • Dashboard sign-in sessions expire after 30 days. Users can also sign out to clear their browser session.
  • AI conversation context is temporary in-memory data and is not persisted to disk by the Service.
  • Ticket transcripts and moderation/event logs posted to Discord remain subject to the server's message retention, access and deletion settings.
  • Music history in the dashboard is stored locally in the user's browser, not in the bot's server-side database.

4. Service providers and sharing

The Service does not sell personal information and does not use it for advertising. Information may be processed by these providers when the related feature is used:

  • Discord: account authentication, server, channel, role and message/interaction features.
  • Railway: hosting for the bot, dashboard and configured persistent storage.
  • Groq: receives AI prompts and limited recent context when the AI feature is enabled and invoked.
  • Music and streaming providers: music source and media extraction providers may receive search terms or media links to resolve playback. Twitch, YouTube/Google or Kick may be contacted to check configured live-stream alerts.

These providers process information under their own terms and privacy policies. AI prompts are not sent to Groq when AI is disabled or not invoked. Stream-alert creator names are sent to a relevant platform only when that integration is used.

5. Access, choices and deletion requests

Server administrators control which optional features are enabled, which channels receive logs and transcripts, and which permissions the bot receives. Administrators can clear warnings using the warning-management commands. Other saved feature data can be removed by the server administrator or Service operator from the relevant bot storage. Removing the bot from a server stops its server features, but does not automatically remove messages, transcripts or records already posted or stored.

To ask about personal information or request access, correction or deletion of data held by the Service, contact the developer through the project support page on GitHub. Do not include sensitive personal information in a public issue; ask for a private way to provide details. Requests may require enough information to identify the relevant Discord server and account.

6. Security

The dashboard restricts management functions to users with server-owner, Administrator or Manage Server permissions and uses signed, secure session cookies. Persistent files are stored on the configured hosting volume. No internet service can guarantee absolute security; server administrators should manage bot permissions, staff access and backups carefully.

7. Children's privacy

The Service is intended for use within Discord and is not designed to collect information directly from children. Users must meet the minimum age required by Discord and the laws that apply to them.

8. Changes and contact

This Policy may be updated when the Service's features or data practices change. The latest version will be published at this URL. For privacy questions or requests, use the project support page and avoid posting personal data publicly.

HARD BOY is an independently operated application and is not affiliated with Discord, Inc.
